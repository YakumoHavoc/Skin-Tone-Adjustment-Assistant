# 修图助手 v1.2

macOS 端的肤色调色建议工具：屏幕上一键取色，直接告诉你 Photoshop「可选颜色」里每个滑块该动多少。

- **快捷键取色**：默认 `⌃⌥C` 唤出系统取色放大镜（全局生效，任何应用里都能取）；可在「肤色取色」面板里点「更改快捷键」直接按下新组合键自定义（至少含 `⌃` / `⌥` / `⌘` 之一，Esc 取消，`⌫` 恢复默认），设置会被记住
- **色盘定位**：取色点在色相环上的位置、它的互补点、目标肤色、健康肤色区间一并标出
- **偏色诊断**：按「偏红 / 偏橙 / 偏灰偏脏 / 偏黄偏冷 / 较为均衡」分类，给出通道级加色与提亮量
- **去灰建议**：互补色以 50% 相混就会变灰，所以「减补色 = 加主色」，据此给出让颜色变干净的力度
- **肤色 / 非肤色分类**：自动判定，也可手动指定；极端环境下按「肤色还原」给三步建议
- **照片仿色**：从左侧侧边栏切到同一个窗口的另一个功能区（不另开窗口）；导入参考图与待仿色图（点卡片选择，或把图片从 Finder 直接拖进卡片），先给影调、再给色调的 Photoshop 仿色建议，细化到菜单路径与要拖的滑块
- **文件名对应**：左选原图文件夹、右选模特修脸返图的文件夹，按**画面内容**（不看文件名）逐张比对，把返图那串英文数字的名字改回原图的名字；改名的同时把原图的 Exif / IPTC / TIFF 拍摄信息**无损**补回返图（修图软件导出时剔掉了这些）；先预览再执行，可一键撤销
- **可隐藏侧边栏**：左侧栏「肤色取色 / 照片仿色 / 文件名对应」一键切换，切换时已导入的照片与文件夹不会丢；收起后用窗口左上角的侧边栏按钮恢复
- **命令行模式**：`--analyze #RRGGBB` 打印调色建议，`--match 参考图 待调图` 打印仿色建议，`--rename-folders 原图夹 返图夹` 打印改名预览（加 `--apply` 执行改名并回填 Exif / IPTC / TIFF）

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS 13.0 及以上 |
| 架构 | Apple Silicon（arm64），构建脚本固定 `arm64-apple-macos13.0` |
| 权限 | 无需屏幕录制、无需辅助功能、无需网络 |

取色用的是系统自带的 `NSColorSampler` 放大镜，全局热键走 Carbon `RegisterEventHotKey`，所以不会弹任何授权窗口。

## 快速开始

```bash
# 编译并打包成可双击运行的 App
./build.sh

# 启动
open "Build/修图助手.app"
```

构建产物为 `Build/修图助手.app`（含自定义图标与临时签名）。启动后按 `⌃⌥C` 开始取色。

## 使用流程

整窗分为**左侧可隐藏侧边栏**与**右侧功能区**两部分。侧边栏的「肤色取色 / 照片仿色 / 文件名对应」切换的是同一个窗口里的内容，不会新开窗口，切换也不会清掉另外两个功能区已经导入的照片或文件夹；侧边栏收起后，点窗口左上角的侧边栏按钮即可重新展开。

### 肤色取色

右侧功能区又分三栏：**左柱**当前取色与数值，**中柱**色相环，**右柱**调整建议。

1. 按 `⌃⌥C`，在皮肤中性区域（颧骨、额头等）单击取色
2. 左柱色块会打上分类标记「肤色 · 橙」或「非肤色 · 青蓝」；色盘标出取色点、互补点与目标肤色
3. 右柱「诊断」说明判定依据，「第 N 步」给出「可选颜色」通道级操作并写明 Photoshop 里的菜单路径，照着调即可
4. 取过的颜色会进入历史记录（最多 16 条），点一下即可切回

左柱还支持手动输入十六进制颜色（`#RRGGBB`）直接分析，不必真的去屏幕上取。

#### 肤色建议落到 Photoshop 的具体控件

右柱每条建议都带一行「操作」，写清进哪个对话框、选哪个通道、动哪些滑块：

| 步骤 | Photoshop 里的操作 |
| --- | --- |
| 压红 / 压橙 | 「图像 › 调整 › 可选颜色」（没有快捷键；或用调整图层：图层面板底部第 4 个图标 › 可选颜色）→ 顶部「颜色」选「红色」或「黄色」→ 拖底部滑块；注意底部只有「青色 / 洋红 / 黄色 / 黑色」四个滑块，加蓝写作「黄色」负值，提亮写作「黑色」负值 |
| 补彩度（偏灰偏脏） | 同上 → 顶部选「中性灰」→ 用「洋红＋黄」补红、「黄＋青」补绿、「青＋洋红」补蓝 |
| 提亮 / 压暗 | 「曲线」（⌘M）把曲线中段整条往上抬；或「可选颜色 · 中性灰」把「黑色」滑块拖到负值（压暗则拖正值） |
| 加暖（偏黄偏冷） | 「可选颜色」顶部选「中性灰」→「洋红」即加红减绿、「黄色」即减蓝；青味重就改选「青色」通道、绿味重改选「绿色」通道 |
| 极端环境还原 | 「可选颜色」顶部选「中性灰」（整幅被染时选「白色」）→ 先把环境色对应的补色加上去洗掉它，再按明度 / 彩度归位 |
| 去灰 | 「可选颜色」顶部选「中性灰」→ 把补色换算成底部滑块：青 / 洋红 / 黄 同名拖负值，红 ⇒「青色」正值、绿 ⇒「洋红」正值、蓝 ⇒「黄色」正值 |

所有步骤都建议用**调整图层**（图层面板底部第 4 个图标）而不是「图像 › 调整」里的即时命令：原图不被破坏、数值随时可回改。

### 照片仿色

1. 在侧边栏切到「照片仿色」
2. 导入两张图：**点卡片**用系统面板选，或者**直接从 Finder 把图片拖到卡片上**（空卡片、已载入的卡片都接受拖放，拖到已载入的卡片上就是替换）
3. 两张图都就位后，下方自动给出五区影调对比、第一步仿影调、色相带对比、第二步仿色调
4. 按建议在 Photoshop 里操作；每一条都写了菜单路径与要拖的滑块

### 文件名对应

模特修脸返图的名字常是一串英文数字，和发出去的原图名对不上。这个功能区按**画面内容**把两边配起来，再把返图改回原图的名字。

1. 在侧边栏切到「文件名对应」
2. 左侧选**原图文件夹**（名字正确的那一侧），右侧选**返图文件夹**（名字是乱码的那一侧）；点卡片用系统面板选，或者**直接从 Finder 把文件夹拖到卡片上**
3. 两个文件夹都选好后会自动扫描比对，也可以随时点「扫描并预览匹配」重来一次
4. 在「匹配预览」里逐行核对：返图名 → 目标名、差异（128 位内容指纹里不同的位数）、判定。带底色的一行才会被处理（改名，或名字已对只补拍摄信息）
5. 确认无误后点「执行重命名并补回拍摄信息」——名字与目标不同的改名；名字本来就一致的不改名，但同样会把对应原图的 Exif / IPTC / TIFF **无损**补写进返图（像素不动，见下节）
6. 改错了点「撤销本次重命名」，按逆序把整批还原

判定为「疑似」的行默认不改名（可用「包含疑似匹配」一并处理），原因会写在行下：原图里两张都像、构图比例差得多（可能裁过）、或同一张原图已被另一张返图以更小的差异命中。

## 调色逻辑

理想肤色参考点取 **H 27° / S 42% / B 78%**，健康区间为 **H 15°–45°、S 25%–62%、B 60%–85%**。

| 判定 | 触发条件 | 处理思路 |
| --- | --- | --- |
| 偏红 | 色相在红区（≥ 340° 或 < 15°）且红分量明显偏高 | 只进「红色」通道：加青 `5+16·sev`、加蓝 `3+9·sev`（蓝是青的支持色），最后提亮 |
| 偏橙 | 色相在红—黄之间（15°–45°）且暖度高 | 分三步：红色通道（加青、加蓝）→ 黄色通道（加蓝、加青）→ 整体提亮 |
| 偏灰偏脏 | 饱和 < 16%，或彩度低且偏暗 | 「中性灰」通道补三原色，配比 **红 : 绿 : 蓝 ≈ 1 : 0.85 : 0.67**，再提亮 |
| 偏黄偏冷 | 色相落在黄 / 绿 / 青 / 蓝一侧 | 「中性灰」通道加暖（洋红 + 黄），必要时再压青或压绿，最后轻微提亮 |
| 较为均衡 | 色相 15°–45°、饱和 25%–62%、明度 60%–85% 三项都在健康区间内 | 只做微量提亮与极小的青色，宁小勿大 |

`sev` 为偏离度（0–1），由色相偏差、饱和度、暖度加权得出——越偏离区间，给的量越大。目标肤色由取色点向理想肤色插值，比例 `0.28 + 0.42·sev`。

## 去灰建议（减补色 = 加主色）

互补色以 50% 不透明度相混就会变成灰色，所以颜色发灰就是补色混进来的证据：**减掉补色与加上主色是同一件事**。

- 六个基准色与互补色：红↔青、黄↔蓝、绿↔洋红
- 相邻两色的中间色组成十二色相环：红、橙、黄、黄绿、绿、青绿、青、青蓝、蓝、蓝紫、洋红、紫红
- 定位：色相落在哪两个基准色之间，距基准色 15° 以内单独成路，否则按两者权重分配（正好对应十二色相环的 30° 分区）
- 灰化程度 `= (1 − 饱和度) + max(0, 0.35 − 明度) × 0.6`，力度 `base = 4 + 15 × 灰化`，单路取全量、双路按权重分配
- 举例：减去黄色蓝天更蓝；减去绿色花变品红；减去品红草地更绿；橙色不在六色里，加红加黄就等于减青减蓝

## 肤色 / 非肤色分类

先做硬性排除，再用加权匹配度判定：

1. 明度 < 12% → 非肤色（深色）
2. 明度 > 95% 且饱和 < 12% → 非肤色（近白，高光或白点）
3. 饱和 < 8% → 非肤色（中性灰）
4. 色相落在 85°–338°（绿 / 青 / 蓝 / 洋红一侧）→ 非肤色，肤色只可能出现在暖区
5. 其余按 **色相 0.45 + 饱和 0.25 + 明度 0.15 + 暖度 R−B 0.15** 计算匹配度，**≥ 55% 判为肤色**

分类结果会体现在色块徽标、色盘标题、诊断卡片与历史摘要上。非肤色时不显示「偏红 / 偏橙 / 偏黄偏冷」这类肤色专用结论，也不给目标肤色。

### 手动指定

左栏「判定方式」可切换 **自动 / 肤色 / 非肤色**。手动值覆盖自动判定，并且跨取色保持（有色光源下整张画面通常都要同样处理），随时可切回「自动」。

手动与自动不一致时走两条专门分支：

**手动 = 肤色（自动认成非肤色）→ 极端环境肤色还原**，判定为「极端偏色」：

1. **洗掉环境色**：色相环上离它最近的家族色就是环境染上的颜色，在「中性灰 / 白色」通道减掉它（等同加它的补色），双路时按 0.85 : 0.6 分配力度
2. **明度归位**：> 88% 压暗，< 40% 提亮，已在区间内则轻微提亮
3. **彩度归位**：< 25% 补红 / 绿 / 蓝回彩度；> 62% 加补色把彩度压回肤色区间

诊断指标额外给出「肤色匹配度 / 主色偏色 / 色相偏差 ΔH」，原理要点里会提示：画面中若有已知中性灰物体或灰卡，先做白平衡再微调肤色最稳。

**手动 = 非肤色（自动认成肤色）→** 不给出肤色步骤，也不给目标肤色，只保留「去灰建议」——即只针对颜色本身处理。

## 照片仿色

照片仿色**与取色不是两个窗口**：它由左侧可隐藏侧边栏切换，与取色共用同一个窗口，导入的图片在切来切去时不会丢。
导入**参考图**与**待仿色图**（点卡片选择，或把图片从 Finder 直接拖进卡片）后自动比对整图的影调与色调，
输出 Photoshop 里的具体操作。核心原则来自实战总结：**先仿影调，再仿色调**。

### 影调：先收掉两端的极端值

统计每张图的明度直方图，按 Photoshop 的说法分成五区：

| 区域 | 区间 | 说明 |
| --- | --- | --- |
| 最暗部 | 0–63 | 有它画面就「硬」，没有它画面就柔和 |
| 暗部 | 64–127 | |
| 中间调 | 128–191 | 画面的主体 |
| 亮部 | 192–223 | |
| 最亮部 | 224–255 | 过多就是死白 |

同时取 1% 分位（最暗部边界）、99% 分位（最亮部边界）与中位数，据此给出：

- **减少最暗部**：待调图的最暗部比参考图更深 → 色阶「输出黑场 0 → 参考图的黑场值」，把最暗部整档抽掉
- **减少最亮度**：待调图的最亮部比参考图更亮 → 色阶「输出白场 255 → 参考图的白场值」
- **防止发灰**：抬黑压白之后画面会变平，按「压缩后中间调落点」与「参考图中位数」的差值，用曲线微调
  「输入 128 → 输出 128 ± 差值」——参考图更暗就压暗，这就是「中间调变暗一点，柔和但不发灰」
- 反向的情况（参考图更有反差 / 更有两端信息）会自动改走「输入黑场」「输入白场」的建议

### 色调：拉满饱和度做比对，再逐带校正

分两个层面统计，都只在彩度 ≥ 15% 的像素上进行：

- **六个色相带**（红 330°–30°、黄 30°–90°、绿 90°–150°、青 150°–210°、蓝 210°–270°、洋红 270°–330°）
  正好对应「色相/饱和度」里可选的六个范围，给出每带的**平均色相**与**平均饱和度**差异
- **整体色相**用 sin/cos 加权做循环平均，避免 0°/360° 附近求平均出错

建议按这个顺序给：

1. 先把「色相/饱和度」的**饱和度滑块临时拉满**（+70 左右）放大色差——颜色光靠眼睛不好比对
2. 全图色相往参考图方向转多少度
3. 逐带选「红 / 黄 / 绿 / 青 / 蓝 / 洋红」，校正色相与饱和度——对着参考图哪里不同就调哪里
4. 需要偏冷暖时用「色彩平衡」补一刀（青–红、黄–蓝）
5. 感觉差不多了，把**全图饱和度改回 0**

> 说明：第 1 步与第 5 步说的「饱和度拉满 / 改回 0」是**比对手法**（临时放大色差用的工作状态），
> 不是最终画面的目标值。

### 落到 Photoshop 的具体控件

每条建议都带一行「操作」，写清菜单路径与要动哪个控件：

| 建议 | Photoshop 里的操作 |
| --- | --- |
| 色阶 · 输出黑场 | 「图像 › 调整 › 色阶」（⌘L）→ 右下角**「输出色阶」**那排**左**滑块向右拖（画面最暗部被抬起来） |
| 色阶 · 输出白场 | 同上 → **「输出色阶」右**滑块向左拖（画面最亮部被压下来） |
| 色阶 · 输入黑场 / 白场 | 同上 → 上方**「输入色阶」**的左 / 右滑块（按住 Option 拖动可实时看裁切） |
| 曲线 · 中间调 | 「图像 › 调整 › 曲线」（⌘M）→ 在横坐标**「输入 128」处单击一次打上锚点**，再按住它上下拖；也可在下方「输入」框直接键入 128 |
| 曲线 · 对比 | 「曲线」（⌘M）→ 在约 1/4（64）与 3/4（192）处各加一个锚点，拉成小幅 S 形 |
| 色相/饱和度 · 全图 | 「图像 › 调整 › 色相/饱和度」（⌘U）→ 顶部下拉保持**「全图」**→ 拖「色相」「饱和度」 |
| 色相/饱和度 · 单带 | 「色相/饱和度」（⌘U）→ 顶部下拉改选「红 / 黄 / 绿 / 青 / 蓝 / 洋红」→ 底部出现该色的**色相条**，先把两端四个滑块收拢到画面里对应颜色的位置，再拖上面两条滑块 |
| 色彩平衡 | 「图像 › 调整 › 色彩平衡」（⌘B）→ 色调平衡选**「中间调」**→ 勾上**「保持明度」**（否则一动颜色亮度跟着变）→ 拖「青–红」「黄–蓝」 |

**两步都用「调整图层」做**（图层面板底部第 4 个图标 › 色阶 / 曲线 / 色相/饱和度 / 色彩平衡），
而不是「图像 › 调整」里的即时命令：原图不被破坏、数值随时可回改，
而且**图层在面板里的堆叠顺序就是执行顺序**——影调层在下、色调层在上，从上往下读一遍就是一整套流程。

> 注意：「色相/饱和度」顶部下拉的六个范围（PS 预设边界）与本文按 60° 分出的六个色相带略有出入，
> 下拉里选不到合适范围时，用十二色相环定位（如橙色 = 加红加黄 = 减青减蓝）。

## 文件名对应（返图按原图改名）

模特修脸返图后，文件名常被重命名成一串英文数字，和发出去的原图对不上，后期整理时只能一张张看。这个功能区不靠文件名、只靠**画面内容**把两边配起来，再把返图改回原图的名字。

### 内容指纹：只记「哪边更亮」

用的是感知哈希（dHash）：

1. 用 ImageIO 把图缩到 128px（顺带按 EXIF 把方向摆正），避免读全尺寸大图
2. 再画进两张极小的灰度格：**9 列 × 8 行**与 **8 列 × 9 行**（灰度只取明暗，与颜色无关）
3. 逐格比较相邻格的明暗：前者更亮记 1、否则记 0。横向 64 位、纵向 64 位，合起来 **128 位内容指纹**

关键在于它**只保留「哪边更亮」这种相对关系**：整体调亮 / 压暗、加对比、重新压缩、轻微修脸，都不会改变这些高低关系；而画面结构不同的照片会差出几十位。所以同一张原图和它的修脸返图，指纹几乎一致。

### 匹配与判定

每张返图去和**所有**原图比一遍，取差异最小的一张：

| 差异（共 128 位） | 判定 | 处理 |
| --- | --- | --- |
| ≤ 24 | 匹配 | 列入改名计划，带底色显示 |
| 25 – 44 | 疑似 | 默认不改名，原因写在行下；勾选「包含疑似匹配」才一起处理 |
| > 44 | 未匹配 | 原图文件夹里没有对应照片，只显示最接近的那张 |

出现下面任一情况，即使差异很小也会**降级为「疑似」**，不自动改名：

- 原图里有两张都像（最优与次优的差距 < 6）——比如连拍、同场景多张，容易张冠李戴
- 构图比例与原图相差超过 6%——很可能被裁过
- 同一张原图被两张返图同时命中——只保留差异最小的那条，另一条降级

### 执行与撤销

- 改名**只发生在返图文件夹**，原图文件夹一个字都不会动（对原图文件夹是只读）
- 目标文件名 = 命中原图的完整文件名；与本文件夹里**别的**文件重名时会跳过并计入报告，**绝不覆盖**。若返图文件名本来就与目标一致，则**不改名**（改反而会互相占名），但仍然会走下面的拍摄信息回填
- 同一批里先用带前缀的临时名把文件全部错开，再落到目标名，避免两个文件互相占用名字；落不到目标名会还原成原名，不留半成品
- 执行过的每一条都被记下来，「撤销本次重命名」按逆序还原（记录只在本次运行内有效）

### 拍摄信息回填（Exif / IPTC / TIFF）

修图软件导出返图时，通常会把原片的 **Exif、IPTC、TIFF** 三段信息一并剔除，交到客户手里就只剩一张「干净」的图。所以处理每一对命中的照片时，都会顺手把对应原图的这三段信息补回返图——**改名的那批补，文件名本来就一致的也补**（后者不动文件名，只补信息，预览里会单列「只补写拍摄信息」的条数）：

- 信息从**命中的那张原图**取，原图文件本身不动
- **不重新编码像素**：走的是 ImageIO 的无损通道 `CGImageDestinationCopyImageSource`，它只重写元数据段。返图的压缩数据与像素**逐字节保持原样**，不会产生二次压缩的画质损失（文件只会因为多了元数据段而变大）
- 原图这几段信息为空的（例如相机/软件导出时就是干净的），**自动跳过**并计入报告
- 下面三个标签**故意不照抄**，否则会把返图写坏：
  - `exif:PixelXDimension` / `exif:PixelYDimension`——返图可能被裁切或换了尺寸，照抄原图尺寸会让元数据与实际画面矛盾（实测确实会写错）
  - `tiff:Orientation`——原图若带 90°/270° 旋转标记，而返图导出时像素已经摆正，照抄会让返图在看图软件里显示成歪的

执行结果里会分别列出「已补写 / 原图没有该信息自动跳过 / 补写失败」的张数，并注明其中有多少是**文件名未变、只补信息**的。撤销只还原文件名，**已经补上的拍摄信息会留在文件里**（原图那份信息本来就不在返图上，无法"还原"）。

已知取舍：IPTC 的 `DateCreated` / `TimeCreated` 这两个日期字段在元数据往返中可能不会保留成 IPTC 段（会以 XMP 形式存在）；拍摄日期本身在 Exif 的 `DateTimeOriginal` 里仍然完整。


## 已知限制

- 单点取色，不做人脸识别或区域平均，建议取皮肤的中性过渡区而不是高光或阴影
- 判定基于颜色统计，不区分光照来源；极端有色光下自动分类可能认错，此时用手动指定
- 「较为均衡」按三项指标同时落在健康区间判定，阈值是硬边界（色相 45°、明度 85% 等），刚好跨过边界时结论会跳变
- 建议值面向 Photoshop「可选颜色」通道语义（青色 / 洋红 / 黄色 / 黑色），其他软件需按对应滑块换算
- 手动指定会跨取色保持，切换回「自动」即恢复
- 照片仿色按**整图平均**给出建议，不做区域 / 蒙版级比对：一张图里若只有局部（如天空、肤色）需要仿，
  「色相/饱和度」里仍要自己选范围或加蒙版；图片会缩到 640px 再统计，速度优先
- 照片卡片只接受**文件 URL** 的拖放（从 Finder 拖图片文件）。从浏览器网页里直接拖图片，或拖的是图片原始数据而非文件，
  不会被识别——这类情况请先把图片存到磁盘，或改用点卡片选择
- 拖拽导入依赖系统拖放会话，无法用命令行脚本自动复现验证，需要手动从 Finder 拖一张图确认
- 文件名对应按**整图内容指纹**匹配：修脸、调色、加锐、重新压缩都不影响判断；但返图若被大幅裁切、加了边框或水印，指纹差异会变大，可能落到「疑似」需要人工确认
- 文件名对应只处理**当前文件夹里**的图像文件，不递归子文件夹；可识别的扩展名为 jpg / jpeg / png / tif / tiff / heic / heif / bmp / gif / webp / avif 与常见 RAW（解码不成功的会跳过并计入报告）
- 返图文件夹里若已有与目标同名的**别的**文件，那一条会被跳过并计入报告，**不会覆盖**任何已有文件（返图自己的名字恰好就是目标名时不算冲突，它只是不改名、照常补拍摄信息）
- 改名只发生在返图文件夹；「撤销本次重命名」的记录只保留在本次运行内，关掉 App 后不再能撤销（文件本身已经改好，不受影响）
- 拍摄信息回填对 JPEG / PNG / TIFF / HEIC 实测可用；个别格式或加密 / 只读文件写不进去时，那一条只改名、补写记为失败并列出原因（不会损坏原文件）
- 回填的元数据来自 ImageIO 的往返转换，IPTC 的 `DateCreated` / `TimeCreated` 可能不保留成 IPTC 段（会以 XMP 形式存在）；拍摄日期在 Exif 的 `DateTimeOriginal` 里仍完整
- 撤销只还原文件名，已经补上的拍摄信息会留在返图里
